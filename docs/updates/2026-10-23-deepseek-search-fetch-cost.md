# 用户越爱用联网，固定月费越容易亏：给 Agent 的搜索和抓取设费用边界

Budget server-side search and fetch separately from model tokens.

资料核实：2026-10-23（北京时间）。本文解读 DeepSeek 官方公开规则，未调用其 API，不代表 CodingRouter 的价格或功能支持。

固定月费鼓励用户多用，按次计费却会随任务增长。对 AI SaaS 和 Agent 团队，真正要决定的不是联网开不开，而是谁承担超出预期的搜索和抓取量。本文帮助你拆账、设限，再选择订阅或超额规则。

## 先分清哪部分费用会变化

DeepSeek 于 2026-10-17 开放 Search/Fetch API。当前价格页列出：Search 与 Fetch 分别为每 1,000 次成功请求 5 元。

DeepSeek Harness、Claude Code、Codex 中使用 DeepSeek API 所触发的这部分服务端工具调用，目前暂未计费，将从北京时间 2026-11-01 00:00 起按次收费。这个范围不能扩大成“所有工具、所有平台都涨价”，也不能写成今天已经开始扣费；独立 Search/Fetch API 的一般价格与指定集成的暂免期要分开看。

## HTTP 200 不一定等于要收费

官方指南说明，只有返回 HTTP 200 且 Search 的 `results` 非空，或 Fetch 返回网页正文，才计这项工具费。失败、无搜索结果或超时不计工具费；`count` 只改变返回条数，不改变单次请求价格。

模型 Token 费用仍需单独计算。因此，“某次搜索不收费”不等于整个任务免费，“一次搜索返回十条结果”也不等于十次 Search 请求。

## 用同一任务的分项记录算账

| 记录项 | 用途 | 容易漏掉什么 |
| --- | --- | --- |
| 模型输入输出与实际费用 | 核对生成部分 | 模型、缓存及实际账单口径 |
| 可计费 Search 请求数 | 核对搜索部分 | 一项任务可能搜索多次 |
| 可计费 Fetch 请求数 | 核对抓取部分 | 搜索到链接不等于已抓取 |
| 任务是否合格、是否完成 | 判断费用有没有产出可用结果 | HTTP 成功不等于业务合格 |

假设一个任务产生 8 次可计费搜索、12 次可计费抓取，按当前公开单价，工具费为 `(8 + 12) × 5 ÷ 1000 = 0.10 元`。这是虚构用量算例，不是实际账单，也未包含模型费用。

先按供应商真实账单规则形成任务总额，再计算每个合格任务的成本。仓库的[离线有效任务成本计算器](../../examples/effective-task-cost/README.md)可以汇总结果，但不会替你识别 Search/Fetch 计费事件；输入前仍要完成费用归属和单位转换。

## 订阅、额度还是超额收费

可以把受控用量包含在订阅内、提供单独工具额度，或明确超额收费。没有对所有业务都最优的统一方案：轻重用户分布、任务完成率和客服解释成本不同，套餐边界也不同。

无论选哪种方案，都应在服务端限制工具调用轮次和单任务预算，接近上限时停止或进入明确确认流程。只在提示词里写“少搜一点”，不能当作费用控制机制。返回状态应说明任务完成、部分完成还是预算耗尽。

## 上线前检查

先用脱敏或合成任务测量调用分布，确认日志能区分请求、可计费成功与业务合格；再核对生效时间、接入方式和费用承担方。本文没有执行收费测试。

截至 2026-10-23，官方指南列出账号级 Search 100 QPS、Fetch 25 QPS，并说明它们与模型并发限制相互独立。QPS 控制瞬时吞吐，不能替代单任务预算、月度额度或超额规则；价格和限制以后仍应回到官方页面复核。
